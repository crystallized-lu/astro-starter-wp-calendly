# Sprint 02 — Bilingual from the start

**Read only this file.** ~4k tokens. Skip entirely if the site is monolingual.

## Goal

Two languages, each with native-language URLs, sharing one nav and footer
dictionary, with correct hreflang and a switcher that never 404s.

## Done when

- `/about-us/` and `/fr/a-propos/` both render, each linking to the other.
- A page with no translation shows no switcher and emits no `hreflang="fr"`.
- Nav and footer strings come from one file, not from per-page duplication.

## The core decision: localized slugs

The lazy option is `/about-us/` ⇄ `/fr/about-us/` — prefix swap, trivial.
Do not take it. French-market search traffic goes to French words, and
`/fr/about-us/` reads as an untranslated afterthought.

So: `/services/ai-orchestration/` ⇄ `/fr/services/orchestration-ia/`.

This costs one thing, immediately. `@astrojs/sitemap`'s `i18n` option can
only express prefix-swap pairing, so it cannot pair localized slugs. Leave it
off and carry hreflang in the document head instead. Note this in the config:

```js
// No i18n block here — EN and FR use different slugs, which the plugin's
// prefix-swap pairing cannot express. Per-page hreflang <link> tags in
// BaseLayout carry the pairing instead.
sitemap({ filter: ..., lastmod: new Date() }),
```

## Astro config addition

```js
i18n: {
  defaultLocale: 'en',
  locales: ['en', 'fr'],
  routing: { prefixDefaultLocale: false },
},
```

English at the root, French under `/fr/`. Page files are written per locale by
hand — this config enables `Astro.currentLocale` without relocating routes.

## `src/i18n/ui.js` — the single source of truth

Plain JS with no framework imports, so both `.astro` server components and
Preact islands can import it.

```js
export const DEFAULT_LANG = 'en';
export const LANGUAGES = { en: 'English', fr: 'Français' };

// Canonical English base path -> French slug. '' is the homepage.
// The English path stays the join key for pairing the two languages, even
// though neither URL contains it on the French side.
export const FR_SLUG = {
  '': '',
  '/about-us': '/a-propos',
  '/contact': '/contact',
  '/privacy-policy': '/politique-de-confidentialite',
  '/services/ai-orchestration': '/services/orchestration-ia',
};

const EN_FROM_FR = Object.fromEntries(
  Object.entries(FR_SLUG).map(([en, fr]) => [fr, en])
);

// The set of translated routes is exactly the keys of FR_SLUG. Adding a
// translation means adding one line here; links and hreflang follow.
export const TRANSLATED_ROUTES = new Set(Object.keys(FR_SLUG));

const stripSlash = (s) => (s.length > 1 && s.endsWith('/') ? s.slice(0, -1) : s);

// Any pathname -> its canonical English base.
export function normalizeBase(pathname) {
  let p = pathname || '/';
  if (p === '/fr' || p === '/fr/') return '';
  if (p.startsWith('/fr/')) {
    const fr = stripSlash(p.slice(3));
    if (fr === '' || fr === '/') return '';
    return EN_FROM_FR[fr] !== undefined ? EN_FROM_FR[fr] : fr;
  }
  p = stripSlash(p);
  return p === '/' ? '' : p;
}

export function langFromPath(pathname) {
  return pathname === '/fr' || pathname === '/fr/' || (pathname || '').startsWith('/fr/')
    ? 'fr' : 'en';
}

function frUrl(base) {
  const slug = FR_SLUG[base] !== undefined ? FR_SLUG[base] : base;
  return slug === '' ? '/fr/' : '/fr' + slug;
}

// Falls back to the English path when no translation exists. This is what
// keeps a partial rollout from producing 404s in the nav.
export function localizedHref(base, lang) {
  const b = normalizeBase(base);
  const enPath = b === '' ? '/' : b;
  if (lang !== 'fr') return enPath;
  return TRANSLATED_ROUTES.has(b) ? frUrl(b) : enPath;
}

// The other-language version of this page, or null if there isn't one.
export function getAlternate(pathname) {
  const base = normalizeBase(pathname);
  if (!TRANSLATED_ROUTES.has(base)) return null;
  const target = langFromPath(pathname) === 'en' ? 'fr' : 'en';
  const enHref = base === '' ? '/' : base + '/';
  const frHref = base === '' ? '/fr/' : frUrl(base) + '/';
  return { lang: target, href: target === 'fr' ? frHref : enHref, label: LANGUAGES[target] };
}

// hreflang entries for <head>. Absolute URLs required by the spec.
export function getHreflangEntries(pathname, origin) {
  const base = normalizeBase(pathname);
  const enHref = origin + (base === '' ? '/' : base + '/');
  const entries = [{ hreflang: 'en', href: enHref }];
  if (TRANSLATED_ROUTES.has(base)) {
    entries.push({ hreflang: 'fr', href: origin + (base === '' ? '/fr/' : frUrl(base) + '/') });
  }
  entries.push({ hreflang: 'x-default', href: enHref });
  return entries;
}
```

An untranslated page still emits `hreflang="en"` and `x-default` pointing at
itself. That is correct and intentional — it declares "this is the only
version" rather than staying silent.

## Chrome strings

```js
export const STRINGS = {
  en: { cta: 'Book a call', switchTo: 'Français', footer: { quickLinks: 'Quick Links', rights: 'All rights reserved.' } },
  fr: { cta: 'Réserver un appel', switchTo: 'English', footer: { quickLinks: 'Liens rapides', rights: 'Tous droits réservés.' } },
};
export function t(lang) { return STRINGS[lang] || STRINGS[DEFAULT_LANG]; }
```

Nav definitions store **English base paths in both languages** and let
`localizedHref` resolve them:

```js
export function getNavLinks(lang) {
  const links = NAV[lang] || NAV[DEFAULT_LANG];
  return links.map((link) => ({
    ...link,
    href: link.href ? localizedHref(link.href, lang) : undefined,
    children: link.children
      ? link.children.map((c) => ({ ...c, href: localizedHref(c.href, lang) }))
      : undefined,
  }));
}
```

So the French nav entry `{ label: "Orchestration d'IA", href: '/services/ai-orchestration' }`
renders as `/fr/services/orchestration-ia`. French labels, English keys — the
translation table stays in exactly one place.

## Three string strategies, used deliberately

1. **Global dictionary** (`i18n/ui.js`) — nav, footer, shared CTAs. Anything
   appearing on every page.
2. **Per-layout bundle** — a local ternary in a layout that needs a dozen
   strings nowhere else. Cheaper than polluting the global dict.
3. **Full page duplication** — body copy. A hand-written `/fr/*.astro` per
   page. Marketing prose is not string-substitutable; forcing it through a
   dictionary produces stilted translations and unreadable templates.

Pick per case. Do not force everything into strategy 1.

## Language switcher

```jsx
function LangSwitcher({ altUrl, altLabel }) {
  if (!altUrl) return null;   // no translation, no switcher — never a 404
  return (
    <a
      href={altUrl}
      lang={altLabel === 'English' ? 'en' : 'fr'}
      aria-label={altLabel === 'English' ? 'View this page in English' : 'Voir cette page en français'}
    >
      {altLabel === 'English' ? 'EN' : 'FR'}
    </a>
  );
}
```

Two details that get missed:

- `lang` on the anchor makes a screen reader pronounce "Français" with French
  phonemes instead of mangling it in English.
- The `aria-label` must be in the language of the **current** page, not the
  target. Hardcoding an English label on French pages is a common bug.

Note `hreflang` uses bare `en`/`fr` while `og:locale` uses `en_GB`/`fr_FR`.
Different specs, different formats. Both are correct as written.

## Partially-translated content

If a section (say, the blog) has French routes serving English bodies during
a rollout:

- `noindex` those pages — they are duplicate English content.
- Wrap the untranslated body in `<div lang="en">` inside the `lang="fr"`
  document, so screen readers switch voices correctly.
- Show a notice saying the translation is in progress.
- Exclude them from `hreflang` even though the switcher still reaches them.
- Do not link to a third-party machine translator. That routes your readers
  through someone else's data processor. The browser's built-in translation
  is the reader's own choice.
